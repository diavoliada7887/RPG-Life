# RPG Live — v0.1

> Ты не обязана выполнить всю карту. Тебе надо прожить своего персонажа.

RPG Live — анти-трекер продуктивности. Он не считает пропуски и не превращает идеи в долги. Его задача — хранить длинную правду о человеке: что он реально делает, во что вкладывается, к чему возвращается и что уже завершил.

## Что есть в первой версии

- главный экран «Сегодня»;
- главный активный квест и ограничение активных сюжетных слотов;
- состояния мира: бафы и дебафы без моральных штрафов;
- быстрый ввод действий по веткам жизни;
- голосовой ввод дневной записи через Web Speech API, если браузер поддерживает;
- «Илья» как игровой мастер/архивариус, который формирует фактологический вердикт по дню;
- журнал квестов: активные, найденные, заблокированные, фоновые, завершённые;
- ветки персонажа с 90-дневным окном вместо стриков;
- механика возвращения после паузы;
- память персонажа и поиск по действиям, дневнику и истории;
- история персонажа — крупные завершённые вещи не исчезают;
- инвентарь идей, где идея не создаёт обязательства;
- карта года по слоям без красных «провальных» дней;
- экспорт данных в JSON;
- PWA: manifest + service worker + офлайн-кэш;
- локальное хранение в localStorage, чтобы прототип сразу работал без аккаунта.

## Запуск

Нужен обычный статический HTTP-сервер — сервис-воркер не работает через `file://`.

```bash
python -m http.server 8080
```

Открыть `http://localhost:8080`.

## GitHub Pages

Репозиторий рассчитан на публикацию прямо из корня ветки `main` через GitHub Pages.

## Почему пока localStorage, а не Supabase

Первая версия должна проверить механику, а не авторизацию. Модель данных уже отделена от интерфейса достаточно, чтобы следующим шагом вынести `quests`, `activities`, `journal`, `states`, `history`, `ideas` и `profile` в Supabase.

## Принципы мира

1. Короткий провал не переписывает длинную правду.
2. Существование идеи не создаёт обязательства.
3. Пустой день не является поражением.
4. Опыт не отнимается за дебафы.
5. Возвращение важнее серии без пропусков.
6. Подготовительный труд меняет состояние будущих дней.
7. Завершённые вещи остаются в истории персонажа.
8. Активных сюжетных линий мало; найденных идей может быть сколько угодно.
9. День — единица записи. Идентичность строится по длинному окну.
10. Приложение не должно превращаться в новую бухгалтерию жизни.
